# 术语表

|术语|含义与边界|
|---|---|
|命名（naming pass）|一次从上下文产出会话名的完整过程，含模型调用与质量校验；不等同于单次模型请求|
|初名|首个文本请求／响应对到达后触发的首次命名，不等待工具执行完毕|
|收口修订|任务落定（agent_settled）时基于完整结果对初名的一次复核，绕过常规冷却，每个任务仅一次|
|周期改名|落定事件时按冷却窗口判断是否让模型复核现有名称；话题未变则保持原名|
|marker|会话历史中的 `pi-autoname-state` 记录，承载名称来源与待修订状态；是恢复依据，不是名称本身|
|provisional|marker 上的标记，表示该名称为初名、仍有待完成的收口修订；reload 后据此继续修订|
|手工名称|用户通过 `/name` 显式设置的名字；`respectManualName` 决定它是否会被自动命名接管|
|冷却窗口|两次自动命名之间的最小间隔（默认十分钟）；收口修订是唯一豁免|
|降级名称|模型调用全部失败后由本地文本提取生成的名称；只用用户文本，绝不使用工具结果|
|质量门|对模型或降级名称的长度与句式校验，作用对象是最终名称字符串|
|提示词线格式|发给模型的固定标记 `<user>` `<assistant>` `<tool-result>` `<current-name>`；与代码内枚举名解耦，改动须同步断言|
|近期证据|命名时使用的上下文窗口：最多六条对话文本、保留最新用户目标，另加最多两条文本工具结果|
|语言判定|仅按用户自然语言消息确定命名语言；助手文本、路径与工具结果不参与|
|扩展注入消息|由其他拓展写入会话的 `custom_message`；是否计入命名由 `includeCustomMessages` 决定|
|标题动画|TUI 模式下终端标题中的忙碌标记，与命名请求分别计数；不写回会话名|

行为与配置以 [README](../README.md) 为正文，本表不复制配置项说明。
